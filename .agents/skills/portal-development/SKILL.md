# 用户端项目工作入口

开始任务时完整读取项目根 [AGENTS.md](../../../AGENTS.md)，已在当前上下文读过完整且未变更时不重复读取。本技能不复制执行限制。

## 工作顺序

1. 明确当前要求是调查、设计、实现还是联调，并区分“已交付文件”“已验证行为”“待实现功能”。涉及面板能力时读取 [对接可行性与功能逻辑](../../../docs/功能逻辑/3x-ui对接与用户自助.md) 中相应章节，按报告记录的源码路径核对目标版本。
2. 选择下面真正适配的技能并读取其入口及要求的参考资料。若技能默认动作与项目约束冲突，在约束内执行可行部分，说明实际缺口。
3. 修改前确认模块职责、用户归属、请求契约、状态变化和失败恢复。对接写操作先核实字段更新语义，不能套用其他 3x-ui 版本的示例。
4. 完成授权范围内的修改和轻量自查，更新对应功能记录。交付包含可打开的文件路径及验证边界；未做运行验证不报告功能已验收。

## 按任务选择技能

| 当前任务 | 读取的技能 | 适配要点 |
| --- | --- | --- |
| 编写项目规则或技能 | `writing-for-agents`；技能文件另加 `skill-creator` | 约束单一维护点，技能按条件路由，检查相对引用 |
| 核查上游 API、版本或认证能力 | `research` | 优先实际源码、官方契约；结论记录证据和版本范围 |
| 设计模块接口或拆解职责 | `codebase-design` | 先明确边界和调用方向，不为分层增加无意义接口 |
| 新建或调整页面、交互与响应式布局 | `impeccable` | 按 React + Ant Design 适配；其他设计技能只在有具体缺口时追加 |
| 故障、错误或性能问题 | `diagnosing-bugs` | 先定位因果和可复现证据；操作仍受执行边界限制 |
| 用户要求测试先行 | `tdd` | 识别需要编译的测试并遵守项目授权，未运行不能宣称红绿闭环 |
| 已有本地服务的浏览器验证 | `webapp-testing` | 先读脚本，核实环境及操作副作用，不自动启动服务或写真实用户数据 |

技能路径从当前会话的可用清单解析，不硬编码某台电脑的技能根目录。没有适配技能时按 AGENTS.md 的缺失处理规则继续可做部分；不把未安装技能写成已经调用。

## 对接工作完成标准

- 查询能区分时间与流量单位、未激活与不限期、面板异常与账号失效。
- 用户请求只能访问已绑定资源，面板凭据未跨越服务端边界。
- 修改操作有明确目标、最小字段、归属检查、部分失败与读回方案。
- 文档中每个“已实现/已验证”均有本轮证据，否则明确写为设计或待联调。
