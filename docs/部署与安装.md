# 部署与安装

门户、3x-ui 可以位于不同服务器。门户使用自己的数据库和密钥；不得把数据目录指向 3x-ui。

## 1. 端口与 HTTPS 选择

| 场景 | 方式 | 验证要求 |
| --- | --- | --- |
| 公网 IP | http | 公网 TCP 80 到验证监听端口；自动使用 shortlived profile |
| 域名，开放 80 | http | 域名 A/AAAA 正确且公网 80 可达 |
| 域名，NAT 只有高端口 | cloudflare | DNS 托管于 Cloudflare，Token 有目标 Zone:Read / DNS:Edit |
| 已有证书或其他 DNS 厂商 | import | 提供包含站点域名/IP 的完整证书链和私钥；续期由原签发工具负责 |
| 隔离测试 | test-self-signed | 仅模拟 HTTPS，不受公网客户端信任 |

网站端口与验证端口独立，例如网站 8443、验证监听 8080，则公网 80 必须映射到内部 8080。SSH 端口与证书验证无关。仅有公网 50001 等高端口不能代替 80。当前集成 HTTP-01 和 Cloudflare DNS-01，没有 TLS-ALPN-01。IPv6 AAAA 指向错误同样可能导致验证失败。

## 2. 从发行版安装

需 root、systemd 或 OpenRC、curl、tar、sha256sum、OpenSSL 和常规用户管理工具。Debian/Ubuntu 可先安装 `ca-certificates curl openssl`。正式证书使用系统可信 CA 库，不支持关闭 TLS 校验。

Alpine 使用 OpenRC，先执行 `apk add bash ca-certificates curl openssl util-linux shadow libcap-setcap`。安装器自动选择 OpenRC，服务使用 supervise-daemon 守护并加入 default 运行级别。`rc-service 3x-ui-portal start|stop|restart|status` 对应 systemctl 操作；日志为 `/var/log/3x-ui-portal/service.log`。低端口权限通过二进制 capability 提供，升级替换后需重新执行 `setcap cap_net_bind_service=+ep /opt/3x-ui-portal/portal`。

```bash
curl -fL https://raw.githubusercontent.com/AngeloSakura/3x-ui-portal/main/scripts/install-linux.sh -o install-portal.sh
sudo bash install-portal.sh https://portal.example.com:8443 cloudflare
# 或 IP / 域名 HTTP-01；公网 80 必须可达
sudo bash install-portal.sh https://192.0.2.10:8443 http
# 内部验证端口可不同，但公网仍需 80
sudo env PORTAL_ACME_LISTEN=0.0.0.0:8080 bash install-portal.sh https://portal.example.com:8443 http
```

示例 IP 为文档保留地址，必须替换。默认下载 latest；可通过 `PORTAL_VERSION=v0.1.0` 固定版本。脚本提示填写联系邮箱、同意 CA 协议；DNS Token 隐藏输入、加密落盘。不填写 3x-ui 密钥到脚本，首次浏览器安装页再设置。

安装路径：程序 `/opt/3x-ui-portal`，数据 `/var/lib/3x-ui-portal`，配置及主密钥 `/etc/3x-ui-portal`。服务以 `portal-svc` 运行，仅数据目录可写。仅授予绑定低端口所需 capability。

```bash
sudo systemctl status 3x-ui-portal
sudo cat /var/lib/3x-ui-portal/setup.token
```

访问 `https://你的主机:端口/install/读到的凭证/`，设置秘密后缀、管理员账号密码、面板完整地址和 admin API Token。安装后安装路由关闭。面板 HTTP 可选，但密钥会明文传输，应使用可信网络。

安装因申请失败而中断时，文件保留供排查；不要删除数据库重新初始化。修复网络或 DNS 后，用下面的 CLI 完成证书；最后从已校验发行包安装 service 文件并启动服务。两次申请至少间隔一小时。

## 3. 证书操作与续期

日常在管理员“站点设置 → HTTPS 证书”查看状态、保存配置、重新申请。新的 DNS Token 留空会保留旧值。测试 CA 证书不受浏览器信任。失败保留旧证书。

自动续期随服务运行，每 15 分钟检查一次；实际有效期消耗约 2/3 时申请，失败至少等一小时。IP 证书约 160 小时，不能套用 30 天续期阈值。成功验证 SAN、有效期、私钥配对后原子替换密文文件并热更新。导入证书未配置 ACME 时不会自动续期。

维护 CLI 前先停服务，避免两个进程覆盖证书状态。以下命令在 root shell 运行，环境文件由安装器生成，只从可信本地读取：

```bash
systemctl stop 3x-ui-portal
set -a
. /etc/3x-ui-portal/portal.env
set +a
# 从标准输入填写 JSON；DNS 凭据不要写进 shell 历史，建议用受限临时文件重定向
/opt/3x-ui-portal/portal tls-config < /root/cert-settings.json
/opt/3x-ui-portal/portal tls-issue
/opt/3x-ui-portal/portal tls-status
chown portal-svc:portal-svc /var/lib/3x-ui-portal/tls-state.enc
systemctl start 3x-ui-portal
```

配置格式：`{"email":"admin@example.com","method":"http","staging":false,"agreeTerms":true}`。Cloudflare 将 method 改为 `cloudflare` 并加入 `dnsToken`。运行后删除临时凭据文件。原有证书导入使用 `PORTAL_IMPORT_CERT`、`PORTAL_IMPORT_KEY` 指向 PEM，再执行 `portal tls-import`。

更换域名/IP 是站点入口迁移：停止服务并备份；修改 `PORTAL_ORIGIN`；把旧 `tls-state.enc` 移到受限备份目录；重新配置/申请或导入匹配新主机的证书，确认权限后启动。登录后缀及账号保留；用户需重新复制本站中转链接。不要只换证书而不改公开地址。变更网站端口同时调整 `PORTAL_LISTEN` 与 NAT 映射。

## 4. 外部 HTTPS 反向代理

可使用 Nginx 等工具：`PORTAL_TLS_MODE=proxy`、`PORTAL_LISTEN=127.0.0.1:8090`、`PORTAL_ORIGIN=https://公开主机:端口`。见 `deploy/nginx.conf.example`，Host 必须保留公开端口。此模式证书交给代理续期，门户后台显示外部管理。不要直接公开 HTTP 后端。

## 5. 源码编译与本地模拟

构建需要 Go 1.26、Node 24、npm、Python 3（打包脚本）；SQLite 使用 pure-Go，无需 GCC/CGO。

```bash
cd frontend
npm ci --ignore-scripts
npm run build
cd ..
go test ./...
go vet ./...
CGO_ENABLED=0 go build -trimpath -o portal ./cmd/portal
./portal init
./portal serve
```

默认只监听 127.0.0.1:8090，公开源为 `http://localhost:8090`，浏览器也必须使用 localhost。PowerShell 用 `$env:变量='值'` 配置，输出 `portal.exe`。

隔离浏览器测试：额外安装 Python `cryptography` 和 Node `playwright`，准备 Chromium；执行 `python3 scripts/smoke-local.py`。可用 `SMOKE_BROWSER` 指定现有 Chrome 路径。脚本只使用临时数据库、模拟面板、自签测试证书，完成后关闭服务；截图保存在被忽略的 `.local`。

Linux 打包示例：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/portal-linux-amd64 ./cmd/portal`，再执行 `python3 scripts/package.py --arch amd64`。arm64 同理。GitHub tag 工作流生成两种架构与 SHA256SUMS。

## 6. 备份、升级与恢复

停止服务后一起备份 `/var/lib/3x-ui-portal` 和 `/etc/3x-ui-portal`，加密保存，切勿上传 GitHub。主密钥与数据库、证书密文必须匹配。SQLite WAL/SHM 若存在需一并备份，避免在线直接复制不一致快照。

升级先校验发行包 SHA256SUMS，停止服务、备份；只替换 `/opt/3x-ui-portal/portal`、`web` 和经过对比的 service 文件，保留数据、主密钥、portal.env。核实数据库版本；当前为 2，版本 1 需按 [SQL 说明](sql/README.md) 手动迁移。启动不自动迁移，`init` 不是升级命令。失败时停止服务，恢复匹配的旧程序/前端/数据库与密钥。

卸载先停止并禁用服务，按需删除程序/service 文件；数据和密钥由管理员明确备份后处理。本项目不提供自动清空数据的卸载按钮。

内存建议至少 128 MiB。安装器设置 Go 软内存目标 `GOMEMLIMIT=40MiB`，不代表硬性内存上限；高并发订阅中转应增加内存。64 MiB NAT 仅适合少量隔离测试，安装脚本不依赖 Python/Go/Node，避免安装运行时占用。
